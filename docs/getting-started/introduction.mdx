<Intro>
  A static MDX documentation generator, with a GitHub [reusable workflow](./github-actions.mdx). It is primarily used for some `pmndrs/*` projects, but will work for anyone.
</Intro>

![Gutenberg lithography](gutenberg.jpg)

[Those projects](https://github.com/search?q=%22uses%3A+pmndrs%2Fdocs%2F.github%2Fworkflows%2Fbuild.yml%22+language%3AYAML&type=code&l=YAML) are known to be using this generator.

## INSTALL

Pre-requisites:

- Install [nvm](https://github.com/nvm-sh/nvm), then:
  ```sh
  $ nvm install
  $ nvm use
  $ node -v # make sure your version satisfies package.json#engines.node
  ```
  nb: if you want this node version to be your default nvm's one:
  `nvm alias default node`

```sh
$ git clone https://github.com/pmndrs/docs.git
$ cd docs
$ pnpm install
```

> Default value is always: `""` (think *empty*).

### Version switcher

The sidebar footer shows the version being browsed: `git describe --tags` of the checkout, eg. `v10.7.9` on a tagged commit, `v10.7.9-3-ga1b2c3d` after it, or `<branch>@<shortsha>` without tags. `LIB_VERSION` overrides it. In a monorepo, or with a moving major tag (`v4`), narrow the tags with `TAG_MATCH`:

| repo tags                  | `TAG_MATCH` |
| -------------------------- | ----------- |
| `v10.7.9`, `v10`           | `v*.*.*`    |
| `leva@0.10.1`, `other@1.0` | `leva@*`    |

Set `VERSION_URL_TEMPLATE`, and the label opens a filterable list of the repo's branches: picking one goes to the same page on that branch's deployment. Without it, the label is all there is. Like `NEXT_PUBLIC_URL`, it is the deployment's full public URL, base path included if it has one (eg. `https://previews.example.com/mylib/{branch}`): the page path is appended to it as is. `{branch}` stands for the branch name, slugified the way your host names its branch URLs:

| placeholder           | `feat/Dark_mode` becomes | host                                                        | example template                                      |
| --------------------- | ------------------------ | ----------------------------------------------------------- | ----------------------------------------------------- |
| `{branch}`            | `feat-dark-mode`         | URLs you create yourself (lowercase, other runs become `-`) | `https://docs-git-{branch}-pmndrs.vercel.app`         |
| `{branch:vercel}`     | `feat-darkmode`          | Vercel Git integration                                      | `https://mylib-git-{branch:vercel}-myteam.vercel.app` |
| `{branch:cloudflare}` | `feat-dark-mode`         | Cloudflare Pages (cut to 28 characters)                     | `https://{branch:cloudflare}.mylib.pages.dev`         |
| `{branch:netlify}`    | `feat-dark-mode`         | Netlify branch deploys                                      | `https://{branch:netlify}--mylib.netlify.app`         |
| `{branch:raw}`        | `feat%2FDark_mode`       | a path or a query string                                    | `https://example.com/preview?branch={branch:raw}`     |

An unknown `{branch:<preset>}`, like an invalid `VERSION_BRANCHES` regex, fails the build.

The branch being built is the one CI names, when it does: `GITHUB_HEAD_REF` then `GITHUB_REF_NAME` (GitHub Actions), `VERCEL_GIT_COMMIT_REF` (Vercel), `CF_PAGES_BRANCH` (Cloudflare Pages), `BRANCH` (Netlify, when `NETLIFY=true`). Otherwise it is git's checked-out branch; a detached `HEAD` is no branch.

`VERSION_PRODUCTION_BRANCH` (default: `main`) is listed first, and leads to `NEXT_PUBLIC_URL` rather than to the template. Any other branch gets a banner on its pages, linking to the same page in production.

The branches are the remote's (`git ls-remote --heads origin`), minus `dependabot/`, `renovate/` and `changeset-release/` ones. `VERSION_BRANCHES` replaces that filter with a regex, eg. `^(?!copilot/|dependabot/)` to also leave out `copilot/` branches; `VERSION_BRANCHES_LIST` skips git altogether, eg. `main,next,v9`. The list is read once, at build time: a deployment keeps the branches of its day, until it is rebuilt.

> [!IMPORTANT]
>
> - The per-branch URLs are yours to create: the switcher only links to them. Vercel's Git integration, Cloudflare Pages and Netlify branch deploys create them. Vercel CLI deployments (`vercel deploy`) do not: give each preview its URL with `vercel alias set <deployment-url> <alias>`, as this repo's [`ci.yml`](https://github.com/pmndrs/docs/blob/main/.github/workflows/ci.yml) does.
> - Git needs the full history and tags: in GitHub Actions, check out with `fetch-depth: 0` (the [reusable workflow](/github-actions/introduction) does). A build without git simply shows no label.

## Usage

### dev

```sh
$ (
  trap 'kill -9 0' SIGINT

  export _PORT=60141

  export MDX=docs
  export NEXT_PUBLIC_LIBNAME="Poimandres"
  export NEXT_PUBLIC_LIBNAME_SHORT="pmndrs"
  export BASE_PATH=
  export DIST_DIR=
  export OUTPUT=
  export HOME_REDIRECT=
  export MDX_BASEURL=http://localhost:$_PORT
  export SOURCECODE_BASEURL="vscode://file$(pwd)"
  export EDIT_BASEURL="vscode://file$(pwd)/docs"
  export NEXT_PUBLIC_URL=
  export ICON=
  export LOGO=gutenberg.jpg
  export GITHUB=https://github.com/pmndrs/docs
  export DISCORD=https://discord.com/channels/740090768164651008/1264328004172255393
  export THEME_PRIMARY="#323e48"
  export THEME_SCHEME="tonalSpot"
  export THEME_CONTRAST="0"
  export THEME_NOTE="#1f6feb"
  export THEME_TIP="#238636"
  export THEME_IMPORTANT="#8957e5"
  export THEME_WARNING="#d29922"
  export THEME_CAUTION="#da3633"
  export THEME_STORYBOOK="#ff4785"
  export CONTRIBUTORS_PAT=

  kill $(lsof -ti:"$_PORT")
  npx serve $MDX -p $_PORT --no-port-switching --no-clipboard &

  pnpm run dev &

  wait
)
```

Then go to: http://localhost:3000

> [!TIP]
> If `HOME_REDIRECT=` empty, `/` will not redirect, and instead displays an index of libraries.

### CLI

No clone, no install — the published CLI does the same build:

```sh
$ cd ~/code/pmndrs/react-three-fiber
$ (
  trap 'kill -9 0' SIGINT

  export _PORT=60141

  export NEXT_PUBLIC_LIBNAME="React Three Fiber"
  export NEXT_PUBLIC_LIBNAME_SHORT="r3f"
  export BASE_PATH=/toto
  export HOME_REDIRECT=/getting-started/introduction
  export MDX_BASEURL=http://localhost:$_PORT
  export ICON=🇨🇭
  export GITHUB=https://github.com/pmndrs/react-three-fiber

  npx -y @pmndrs/docs@latest build docs docs/out --format website

  kill $(lsof -ti:"$_PORT")
  npx serve docs -p $_PORT --no-port-switching --no-clipboard &

  npx -y serve docs/out &

  wait
)
```

Then go to: http://localhost:3000

Every option above has a flag too — `npx @pmndrs/docs@latest build --help` lists them.
